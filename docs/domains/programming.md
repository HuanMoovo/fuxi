# 领域深潜 · 编程学习

> 伏羲框架 · 万物皆可学 ｜ [系列首页](README.md) ｜ 领域深潜 2/5

编程的难不在单点：语法、语义、策略三层同时加载，新手的工作记忆很容易被「怎么拼写」这类外在细节占满。计算教育研究里最有用的结论，几乎都在替新手省负荷。

## 1. 证据地图

- 编程是典型的高认知负荷技能：新手要从零同时处理语法、算法与调试策略（[C303]）。
- 「读代码」与「写代码」是可分离的技能，教学顺序有讲究：先读、再改、最后从零写（[C302][C300]）。
- 视频是主流入口，但视频的教学设计参数（时长、出镜方式、剪辑节奏）显著影响学生的参与行为（[C301]）。

## 2. 关键方法与其证据

- **子目标标注示例**：给示例代码的每个子目标打标签（「这里在做二分查找」），显著提升新手成绩与迁移（[C303]）。—— 证据：B
- **Parsons 题**：把打乱的代码行拖回正确顺序；入门阶段比从零写更省负荷，适合「读 → 改 → 写」之间的过渡（[C302]）。—— 证据：B
- **PRIMM 序列**：Predict → Run → Investigate → Modify → Make，把「先读后写」排成显式教学序列，有课堂研究支持（[C300]）。—— 证据：B/C
- **调试要显性教**：调试不是「写着写着就会」；教育视角的文献综述建议把调试策略（读错误信息、二分定位、最小复现）列入教学（[C304]）。—— 证据：B
- **教学视频设计**：更短（6 分钟内）、在「头」与「手」之间切换、节奏明快的视频，参与度显著更高（[C301]）。—— 证据：B
- **CS1 教学三件套**：把媒体计算、同伴教学与专业实践放进入门课，掉队显著减少（[C305]）。—— 证据：B

## 3. 十阶落点

| 阶段 | 编程领域的关键动作 |
|---|---|
| ① 立志 | 目标定成可运行的产物（一个工具、一个 PR），而不是「学完 Python」 |
| ② 建图 | 语言特性 → 生态（包管理、测试、部署）→ 调试工具，三层地图 |
| ③ 拆解 | 知识点拆成可练的小题（30–60 分钟一粒） |
| ④ 编码 | 示例 + 子目标标注（[C303]）；亲手重写示例而不是复制粘贴 |
| ⑤ 检索 | 默写高频语法与 API；离开文档把代码写出来 |
| ⑥ 间隔 | 把易错点做成卡片，间隔重刷题库 |
| ⑦ 精练 | 反馈式练习循环（如 Exercism）；Parsons 过渡（[C302]）；刻意练调试（[C304]） |
| ⑧ 实战 | 真项目：别人能用、能提 issue 的产物 |
| ⑨ 教学 | 代码评审、写教程、在社区答题 |
| ⑩ 维护 | 隔月重构旧代码，用真实维护保持手感 |
| ⑪ 拓界 | 贡献开源：从修一个 bug 到提一个 feature |

## 4. 领域专属误区

- 「刷完教程就会写」✗ —— 教程是输入；能力在写、改、调试里增长（[C302][C303]）。
- 「先把数学补到精通再回来」✗ —— 多数应用编程按需补数学，门槛被高估。
- 「必须记住所有 API」✗ —— 更重要的是检索与查文档能力；只把高频易错点做成卡片。
- 「报错 = 失败」✗ —— 报错是反馈信号；会读错误信息本身就是一项要练的技能（[C304]）。
